# AI Companion Content Generation System

## Overview

Holzen is a mindfulness app for Bitcoin holders. When Bitcoin's price moves significantly, the app helps users **pause before making emotional decisions** (panic selling, FOMO buying). It does this by generating personalized content that grounds them.

---

## The Trigger

Two ways a pause session starts:

### Automatic (server-side)
The `check-volatility` cron runs every 15 minutes:
1. Checks BTC price via CoinGecko
2. For each user: did price move more than their threshold? (default 5%)
3. If yes + not in cooldown + not in quiet hours → generates session
4. Sends push notification + email: "BTC moved. Take a moment."

### Manual (user-initiated)
1. User opens app and taps "Pause"
2. Checks cooldown (15 min, or 5s in dev mode via admin Tools tab)
3. Generates session immediately

---

## The Session Flow

```
1. MOOD CHECK
   User selects how they're feeling: calm, anxious, fearful, excited, fomo, greedy

2. REFLECTION (holzen-reflect edge function)
   AI generates a 1-3 sentence reflection + haiku
   Adapts to: tone preference, mood history, severity, motivations, mantra
   Quality gate: no slop, no crypto language, no fake prices, no exclamation marks

3. COMPANIONS (companion-orchestrate edge function)
   Orchestrator determines session intent (theme), then fires 4 generators in parallel
```

## The 5 Content Types

### Reflection
> "The number changed. You didn't."
> + Haiku (5-7-5 syllable structure)

- **Generated by**: Gemini (no search needed)
- **Personalized via**: tone, mood history, motivations, mantra, grounding activities
- **Quality gate**: slop, length (20-500 chars), exclamation marks, fake prices, haiku line count

### Signal (Philosophical Bitcoin Insight)
> "Proof of work is proof of sacrifice" — Gigi

- **Generated by**: Content Library → Perplexity search → Gemini structuring
- **Themed via**: session intent (patience/humility/composure)
- **Quality gate**: slop, crypto language, source attribution, sentence diversity, market data leakage

### Grounding (Behavioral Science)
> "Loss aversion doubles the sting" — Kahneman & Tversky (1979)

- **Generated by**: Content Library → Perplexity academic search → Gemini structuring
- **Themed via**: session intent selects bias topic matching user's emotional state
- **Quality gate**: slop, crypto language, specificity (needs researcher names + years)

### History (Cross-Asset Parallel)
> "Amazon lost 95% and became the everything store"

- **Generated by**: Content Library → Perplexity search → Gemini structuring
- **Themed via**: mood-aware era selection (anxious→recovery, excited→caution, calm→any)
- **Quality gate**: slop, crypto language, specificity (needs dates + numbers)

### Zoom Out (Deep Time + Prices + Echo)
> "Fifteen years in five thousand" + BTC prices 1-4 years ago + your past reflection

- **Generated by**: btc_price_cache (cron-refreshed) + Gemini deep-time + DB echo
- **Themed via**: session intent selects deep-time seed from 18 diverse themes
- **Quality gate**: slop, crypto language, no market data in deep-time

## Session Intent (Coherence Layer)

Before any companion generates, the orchestrator determines a **session theme** based on:
- Market direction (up/down)
- User mood (anxious/fearful/excited/calm/etc.)
- Severity (% change)
- User's selling pattern history

### Example
```
User is anxious, BTC is down 7%
  → Theme: "patience-during-fear"
  → Signal: searches for philosophy about patience/conviction
  → Grounding: selects loss aversion bias (fear-related)
  → History: picks a recovery story (COVID crash, Amazon 95%)
  → Zoom Out: deep-time seed about patience (cathedral builders, geology)
  
Result: ALL companions align to calming/patience/recovery
```

### Available Themes
| Theme | Trigger | Emotional Tone |
|-------|---------|---------------|
| patience-during-fear | Fearful + down market | Calming |
| steadiness-during-anxiety | Anxious + moderate move | Grounding |
| humility-during-euphoria | Excited + up market | Cautioning |
| grounding-during-fomo | FOMO/greedy | Grounding |
| affirmation-of-composure | Calm/detached | Affirming |
| reflection-on-selling | Selling pattern detected | Grounding |
| neutral-exploration | No strong signal | Grounding |

## The Generation Pipeline

Each companion follows this pipeline:

```
Step 1: CHECK CONTENT LIBRARY (local, instant, free)
  → Search content_library table for matching type + tags
  → If found: serve immediately, skip all API calls
  → If empty: continue to Step 2

Step 2: SEARCH (Perplexity sonar-pro, ~3-5s, ~$0.01)
  → Send themed search query
  → Get back: search content + citation URLs
  → If fails (rate limit/timeout): skip to fallback chain

Step 3: STRUCTURE (Gemini, ~1-2s, ~$0.001)
  → Send search results to Gemini with structuring prompt
  → Get back: structured JSON (title, body, source, url)
  → Primary: gemini-2.5-flash → fallback: gemini-3-flash-preview
  → If fails: skip to fallback chain

Step 4: QUALITY GATE (instant, free)
  → Schema check: all required fields present?
  → Length check: body within min/max for type?
  → Slop check: no banned AI phrases? (27 phrases)
  → Bitcoin-only: no generic crypto language?
  → Specificity: researchers+years (grounding), dates+numbers (history)?
  → Source attribution: not generic? Cross-ref with known authors?
  → Sentence diversity: not repetitive structure?
  → If fails: skip to fallback chain

Step 5: SERVE + CACHE
  → Pass: serve to user + write to companion_cache + background URL validation
  → Fail: fall through to fallback chain

FALLBACK CHAIN:
  a. Cache: quality-ranked, per-user dedup, market-direction aware
  b. Curated: 10 hand-written verified entries per type
  c. Empty: (should never reach here)
```

## Content Library

The content library is a local knowledge base that reduces Perplexity dependency.

### Table: `content_library`
| Type | Used By | Fields |
|------|---------|--------|
| essay | Signal | title, author, summary, key_quote, url |
| paper | Grounding | title, author, summary, citation, finding, url |
| event | History | title, summary, event_date, asset_class, analogy, recovery, mood_tag |

### Fed by
1. **Initial seed data** (11 entries from migration)
2. **fetch-source-feeds cron** (Firecrawl scrapes source URLs → Gemini structures → library)
3. **Manual entry** via admin dashboard (Library tab)

### Source Feed Pipeline
```
Admin adds source: "Parker Lewis" → https://unchained.com/gradually-then-suddenly/
        ↓
fetch-source-feeds cron (twice daily):
  → Firecrawl scrapes URL → clean markdown
  → Gemini structures: title, author, summary, key_quote
  → Stored in content_library with proper attribution
        ↓
Next user session:
  → Signal generator searches content_library first
  → Finds Parker Lewis entry → serves instantly (no Perplexity needed)
```

## Cache System

### Table: `companion_cache`
Stores AI-generated content that passed quality gates.

### Quality Scores
| Score | Meaning | Lifecycle |
|-------|---------|-----------|
| 1 | Low (unverified URL) | Pruned after 3 days |
| 2 | Good (verified URL) | Expires after 30 days |
| 3 | Curated/permanent | Never expires |

### Selection Strategy
When serving from cache (fallback):
1. Filter: matching companion type + language + not expired
2. Exclude: entries this user has already seen (`user_companion_serves` table)
3. Prefer: entries matching current market direction (up/down/neutral)
4. Rank: quality_score DESC → last_served_at ASC → used_count ASC
5. Pick: random from top 3

### Lifecycle Management
The `pregenerate-companions` cron (every 6 hours):
- **Promote**: quality_score ≥ 3 → permanent (never expires)
- **Auto-promote**: score ≥ 2 AND served 3+ times → permanent
- **Prune**: score < 2 after 3 days → delete
- **Expire**: medium quality after 30 days → delete
- **Feedback**: thumbs up → score +1, thumbs down → score -1

## Cost Model

### Per session (all 4 companions)
| Source | Cost |
|--------|------|
| Content Library hit | $0.000 (free, local DB read) |
| Perplexity search × 3 | ~$0.015-0.045 (if library misses) |
| Gemini structuring × 4 | ~$0.004-0.012 |
| Reflection (Gemini) | ~$0.001-0.003 |
| **Total** | **$0.00-0.06** depending on library hit rate |

### Budget and limits
- Budget cap: $10/day (enforced in orchestrator)
- Rate limit: 30 sessions/hour/user

### Background costs
- Source feed fetching: ~$0.05/day (5 sources × 2 runs × $0.005 each)
- Cache warming: ~$0.10/day (5 entries × 4 runs × $0.005 each)
- Price refresh: $0 (CoinGecko free tier)

## Security

| Layer | Protection |
|-------|-----------|
| Admin page (frontend) | `VITE_ADMIN_USER_IDS` env var |
| Admin data (server) | `profiles.is_admin` + `is_admin()` function + RLS policies |
| Edge functions | JWT verification via `getUser()` |
| Server-to-server | Service role key verification |
| Rate limiting | 30 req/hour per user via analytics_events count |
| Budget | $10/day cap via generation_attempts cost sum |
| Prompt injection | `sanitizePromptInput` strips control chars + injection patterns |
| Content quality | Quality gates reject slop, crypto language, fake prices |
| Bitcoin-only | `containsCryptoLanguage()` rejects altcoin/generic crypto content |
