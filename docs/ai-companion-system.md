# AI Companion Content Generation System

## Overview

Holzen is a mindfulness app for Bitcoin holders. When Bitcoin's price moves significantly, the app helps users **pause before making emotional decisions** (panic selling, FOMO buying). It does this by generating personalized content that grounds them.

---

## The Trigger

Two ways a pause session starts:

### Automatic (server-side)
The `check-volatility` cron runs every 15 minutes:
1. Fetches BTC moves from **CoinGecko** (`market_chart` 1d + 7d) with retries
2. For each user: compare against their threshold (and cumulative threshold when configured)
3. If yes + not in cooldown + not in quiet hours → builds a **context string** (e.g. “BTC is down 5.2%…”)
4. **Reflection** is generated **inside `check-volatility`** via a local `generateReflection()` helper (Lovable/Gemini) — it does **not** call the `holzen-reflect` edge function (manual pause uses `holzen-reflect` in `use-holzen.ts`)
5. Inserts a `reflections` row, then **fire-and-forget** `POST` to `companion-orchestrate` (service role) with `enableSignal/Grounding/History/ZoomOut` — payload **does not** include `mood`, `severity`, or `moodHistory`, so `determineSessionIntent()` usually falls through to **neutral-exploration** unless you extend that dispatch
6. Sends push + optional email

### Manual (user-initiated)
1. User opens app and taps "Pause"
2. Checks cooldown (15 min, or 5s in dev mode via admin Tools tab)
3. **`holzen-reflect`** generates reflection + haiku (`use-holzen.ts`); then **`companion-orchestrate`** runs from `use-companion-data.ts` with **`mood`** from the mood check (still **no** `severity` / `moodHistory` in the invoke body today — intent uses mood + parsed `context` only)

---

## The Session Flow

```
1. MOOD CHECK
   User selects how they're feeling: calm, anxious, fearful, excited, fomo, greedy

2. REFLECTION
   • **Manual pause:** `holzen-reflect` — full adaptive tone/style, mood history, severity, motivations, mantra, sanitization, haiku
   • **Volatility cron:** reflection only inside `check-volatility` (separate, slimmer prompt path; profile-driven haiku/learning toggles)

3. COMPANIONS (companion-orchestrate edge function)
   Orchestrator determines session intent (theme), then runs the four generators **in parallel, in-process**
   (direct imports of `generateSignal`, `generateGrounding`, `generateHistory`, `generateZoomOut` — not HTTP calls
   to the thin per-type edge functions, which remain for standalone use)
```

## The 5 Content Types

### Reflection
> "The number changed. You didn't."
> + Haiku (5-7-5 syllable structure)

- **Generated by**: Gemini via the **Lovable AI gateway** (no web search)
- **Model fallback** (newest first): `google/gemini-3-flash-preview` → `google/gemini-2.5-flash`
- **Personalized via**: tone, mood history, motivations, mantra, grounding activities
- **Quality gate**: slop, length (20-500 chars), exclamation marks, fake prices, haiku line count

### Signal (Philosophical Bitcoin Insight)
> "Proof of work is proof of sacrifice" — Gigi

- **Primary path**: Perplexity (`sonar-pro`) → **Lovable gateway** (Gemini) structuring → quality gate → optional `companion_cache` write → **`source: "live"`**
- **Fallback** (`serveFallback`): `content_library` (essays, `includeStale: true`) → `serveFromCache` → curated `SIGNAL_FALLBACKS`
- **Structuring models**: `google/gemini-2.5-flash` → `google/gemini-2.5-flash-lite`
- **Themed via**: session intent (`searchAngle`), market direction hints in the search query, `recentSignalSources` / `recentSignalTitles` exclusions
- **Quality gate**: slop, crypto language, source attribution, sentence diversity, market data leakage

### Grounding (Behavioral Science)
> "Loss aversion doubles the sting" — Kahneman & Tversky (1979)

- **Primary path**: Perplexity academic (`sonar-pro` + `search_mode: academic`) → Lovable/Gemini structuring → QG → cache write → **`live`**
- **Fallback**: `content_library` (papers, `includeStale: true`) → `serveFromCache` → `GROUNDING_FALLBACKS`
- **Structuring models**: `google/gemini-2.5-flash` → `google/gemini-2.5-flash-lite`
- **Themed via**: session `preferredBias` when it matches a known bias topic; else random bias from a pool filtered by market up/down and `recentTopics`
- **Quality gate**: slop, crypto language, specificity (needs researcher names + years)

### History (Cross-Asset Parallel)
> "Amazon lost 95% and became the everything store"

- **Primary path**: Perplexity (`sonar-pro`) → Lovable/Gemini structuring → QG → cache write → **`live`**
- **Fallback**: `content_library` (events; optional `moodTag` from mood / `preferredMood`) with `includeStale: true` → `serveFromCache` → `HISTORY_FALLBACKS`
- **Structuring models**: `google/gemini-2.5-flash` → `google/gemini-2.5-flash-lite`
- **Themed via**: era bucket from `selectEra` (mood + `preferredMood` + `recentTitles`), then woven into the Perplexity system/user prompts
- **Quality gate**: slop, crypto language, specificity (needs dates + numbers)

### Zoom Out (Deep Time + Prices + Echo)
> "Fifteen years in five thousand" + BTC prices 1-4 years ago + your past reflection

- **Generated by**: **`btc_price_cache` only** (no CoinGecko call during the user request; cron `refresh-btc-prices` keeps rows fresh) + echo reflection from DB + **Lovable gateway** (Gemini) for deep-time copy
- **Structuring models**: `google/gemini-2.5-flash` → `google/gemini-2.5-flash-lite`
- **Themed via**: session intent (`zoomOutAngle` text from `session-intent.ts`). If that parameter is omitted (e.g. some standalone calls), the generator picks from **18** built-in deep-time seeds for variety.
- **Quality gate**: slop, crypto language, no market data in deep-time

## Session Intent (Coherence Layer)

Before companions run, `companion-orchestrate` calls `determineSessionIntent()` (`_shared/session-intent.ts`) using whatever the **caller puts in the JSON body**: `context`, `mood`, `severity`, `moodHistory` (array of `{ mood, outcome? }`). **Selling-pattern** and **severity-based** branches only apply when `moodHistory` / `severity` are actually sent (today’s `use-companion-data` and `check-volatility` orchestrate dispatch omit most of that; see Trigger section).

Inputs that always matter when present:
- **Market direction** parsed from `context` (“is down” / “is up”)
- **User mood** string when provided
- **Severity** (absolute % change) when provided
- **Mood history** for sell-rate / outcomes when provided

### Example (when `mood`, `context`, and numeric **`severity`** are all supplied, e.g. extended client)
```
User is anxious, context says BTC is down, severity = 7.2
  → Theme: "patience-during-fear" (anxious + severity ≥ 7)
  → Signal: Perplexity query steered by intent.signalAngle (patience / conviction)
  → Grounding: preferred bias from intent (e.g. loss aversion / panic)
  → History: preferredMood "recovery" → recovery-era Perplexity prompt
  → Zoom Out: intent.zoomOutAngle text passed into deep-time generation

Typical manual invoke today sends mood + context but not severity → often "steadiness-during-anxiety" for anxious + down copy, not the high-severity patience branch.
```

### Available Themes (simplified labels — see `session-intent.ts` for exact `if` order)
| Theme | Rough condition (code uses compound checks) | Emotional Tone |
|-------|---------------------------------------------|-----------------|
| patience-during-fear | `fearful`, or `anxious` with severity ≥ 7, or `isDown` with severity ≥ 5 | Calming |
| steadiness-during-anxiety | `anxious` (and not the patience branch above) | Grounding |
| humility-during-euphoria | `excited` and up context, or `isUp` with severity ≥ 5 | Cautioning |
| grounding-during-fomo | `fomo` or `greedy` | Grounding |
| affirmation-of-composure | `calm` or `detached` | Affirming |
| reflection-on-selling | Sell rate more than 30% over at least 3 outcomes **and** down context | Grounding |
| neutral-exploration | Default | Grounding |

## The Generation Pipeline

**Signal, Grounding, and History** (in `_shared/generators/*.ts`) use **live search + structuring first**. The **content library** is used only inside **`serveFallback`**, after Perplexity/structuring/quality gate failure or when API keys are missing.

**Zoom-out** does not use the library or Perplexity: `btc_price_cache` + optional echo reflection + Lovable/Gemini deep-time; on AI failure it uses **`serveFromCache`** then curated (`zoom-out.ts`). **Reflection** stays in `holzen-reflect` only.

### Primary path (happy path — Signal / Grounding / History)

```
1. PERPLEXITY — themed query (session hints, mood, market context, exclusions)
2. LOVABLE / GEMINI — structure tool output or JSON into the companion schema
3. QUALITY GATE — reject slop, missing specificity, etc.
4. OPTIONAL WRITE — insert into companion_cache (dedup by title), background URL validation
5. RETURN — source "live" (even though observability may log cache insert for reuse later)
```

If `PERPLEXITY_API_KEY` or `LOVABLE_API_KEY` is missing, the generator **skips** steps 1–4 and goes straight to **`serveFallback`**.

### Fallback chain (`serveFallback` — same three generators)

```
A. CONTENT LIBRARY — searchLibrary(..., { includeStale: true })
   • No 7-day “freshness” filter on this path (the filter in content-library.ts only runs
     when includeStale is false; companions never call that today).
   • Still applies table filters (type, active, companion_types; History may pass moodTag).
   • Picks randomly among up to the top 3 rows returned; recordLibraryServe updates
     user_companion_serves for analytics/dedup if you reintroduce fresh-only reads later.

B. COMPANION_CACHE — serveFromCache (quality + market + per-user seen; third pass may repeat)

C. CURATED — pickRandom from _shared/fallbacks.ts
```

**End-to-end order for a typical session:** **Perplexity → Gemini → (on failure)** library → cache → curated. That matches a **live-first** product choice; library and cache are **safety nets**, not the first hop.

### Library freshness (code vs current use)

`_shared/content-library.ts` still defines **FRESHNESS_WINDOW_DAYS** (7) and filters “seen recently” when **`includeStale` is false**. As of this generator layout, **only** `includeStale: true` is used from Signal/Grounding/History, so that freshness branch is **unused** for companion serves until you add a pre-Perplexity `searchLibrary` call with the default.

## Cache and “seen” behavior (`companion_cache`)

When reading from **`serveFromCache`** (fallback, and zoom-out deep-time failure):

1. Prefer unseen rows for this user (`user_companion_serves` stores both real cache UUIDs and library row UUIDs depending on serve path).
2. Prefer higher `quality_score`, market regime match, then least recently served.
3. Third pass drops the “exclude seen” filter and may repeat content immediately to avoid empty UI.

There is **no** time-based “eligible again after 7 days” for **cache** rows in this logic.

## Content Library

The content library is a **curated local pool** used when **live generation fails** (or keys are missing): cheaper, attributed essays/papers/events. It does **not** run before Perplexity on the happy path in the current generators.

### Table: `content_library`
| Type | Used By | Fields |
|------|---------|--------|
| essay | Signal | title, author, summary, key_quote, url |
| paper | Grounding | title, author, summary, citation, finding, url |
| event | History | title, summary, event_date, asset_class, analogy, recovery, mood_tag |

### Fed by
1. **Initial seed data** (11 entries from migration)
2. **fetch-source-feeds cron** (Firecrawl scrapes source URLs → Gemini structures → library)
3. **Manual entry** via admin dashboard (Library tab)

### Source Feed Pipeline
```
Admin adds source: "Parker Lewis" → https://unchained.com/gradually-then-suddenly/
        ↓
fetch-source-feeds cron (twice daily):
  → Firecrawl scrapes URL → clean markdown
  → Lovable gateway (Gemini) structures: title, author, summary, key_quote
  → Stored in content_library with proper attribution
        ↓
When live generation fails (or keys missing):
  → serveFallback may pick a matching content_library row (essay/paper/event)
  → Serves without another Perplexity call for that companion
```

## Cache System

### Table: `companion_cache`
Stores AI-generated content that passed quality gates.

### Quality Scores
| Score | Meaning | Lifecycle |
|-------|---------|-----------|
| 1 | Low (unverified URL) | Pruned after 3 days |
| 2 | Good (verified URL) | Expires after 30 days |
| 3 | Curated/permanent | Never expires |

### Selection Strategy
When serving from cache (fallback):
1. Filter: matching companion type + language + not expired
2. Exclude: entries this user has already seen (`user_companion_serves` table)
3. Prefer: entries matching current market direction (up/down/neutral)
4. Rank: quality_score DESC → last_served_at ASC → used_count ASC
5. Pick: random from top 3

### Lifecycle Management
The `pregenerate-companions` cron (every 6 hours):
- **Promote**: quality_score ≥ 3 → set `expires_at` null (permanent)
- **Auto-promote**: score ≥ 2, `used_count` ≥ 3, still expiring → set `expires_at` null **and** `quality_score` to **3**
- **Prune**: quality score below 2 and older than 3 days → delete
- **Expire**: quality score below 3, still has `expires_at`, older than 30 days → delete (does not touch already-permanent rows)
- **Feedback**: thumbs up → score +1, thumbs down → score -1

## Cost Model

### Per session (all 4 companions)
| Source | Cost |
|--------|------|
| Perplexity search × 3 (Signal, Grounding, History) | ~$0.015-0.045 on a normal success path |
| Gemini structuring × 3 (those companions) + zoom-out deep-time | ~$0.004-0.012 (plus zoom-out token use) |
| Reflection (Gemini) | ~$0.001-0.003 |
| Content library (fallback only) | $0.000 when `serveFallback` hits DB instead of curated |
| **Typical happy path** | **~$0.02-0.06** (live-first; no library savings on success) |
| **All-fallback session** | Lower API cost; mostly DB + static fallbacks |

### Budget and limits
- **Daily budget:** `$10` USD (`checkDailyBudget` sums `generation_attempts.estimated_cost_usd` since UTC midnight; enforced in `companion-orchestrate`).
- **Rate limit:** `checkRateLimit(svcClient, userId, 60, 30)` — max **30** events in the last **60 minutes** per user, counting only rows in `analytics_events` whose `event` is in the allowlist in `_shared/ratelimit.ts` (e.g. `pause_ai_call`, `signal_companion_ai_call`, `historical_insight_ai_call`, `zoom_out_ai_call`, …). **`companion-orchestrate` does not insert `analytics_events`**, so orchestrated companion batches are not themselves counted; the limit mainly bounds **reflection** (`pause_ai_call` from `holzen-reflect`) and other listed AI features, not “one tick per companion.”

### Background costs
- Source feed fetching: ~$0.05/day (5 sources × 2 runs × $0.005 each)
- Cache warming: ~$0.10/day (5 entries × 4 runs × $0.005 each)
- Price refresh: $0 (CoinGecko free tier)

## Security

| Layer | Protection |
|-------|-----------|
| Admin page (frontend) | `profiles.is_admin` from DB when available; else fallback to `VITE_ADMIN_USER_IDS` (see `Admin.tsx`) |
| Admin data (server) | `profiles.is_admin` + `is_admin()` function + RLS policies |
| Edge functions | JWT verification via `getUser()` |
| Server-to-server | Service role key verification |
| Rate limiting | Sliding window on selected `analytics_events` types (60 min / 30 max); see Cost Model — orchestrate path not logged there |
| Budget | $10/day cap via generation_attempts cost sum |
| Prompt injection | `sanitizePromptInput` strips control chars + injection patterns |
| Content quality | Quality gates reject slop, crypto language, fake prices |
| Bitcoin-only | `containsCryptoLanguage()` rejects altcoin/generic crypto content |
