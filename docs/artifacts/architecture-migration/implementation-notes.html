How to use this log

This file is the running interpretation audit trail for the architecture migration initiative — not a second spec and not a commit journal.

  • Append an <article class="note"> when a slice involves ambiguity, an intentional spec deviation, a tradeoff reviewers should see, or an unresolved question.
  • Skip entries for routine relocations, test-only parity pins, merge-conflict cleanup, or behavior-unchanged renames — those belong in git history and PR descriptions.
  • One note per decision, not one note per commit. Group related slices under one heading when the interpretation is the same.
  • Record date, slice title (not necessarily commit SHA), spec §, and status (open | resolved | wont-fix).
  • When a question is resolved, add a Resolution paragraph under the same note — do not delete the original.
  • Update the Contents → Running notes list when you add a note with a new anchor id.
  • Permanent target changes → update the owner spec in the same PR; notes are the staging area.

Full workflow: implementation-notes-workflow.md. Agent rule: architecture-migration.mdc.

Agreed baseline

Interpretation we implement toward — not deviations. Owner specs remain normative; this section captures cross-cutting agreements for the initiative.

  • North star: all active src/ (app, screens, components, features, lib) aligns with P1–P9 and the shared module skeleton (pause-client-architecture.md §9).
  • Scheduling: at each slice tier, finish pause before the same tier elsewhere — unless a human names another target.
  • Pause ritual layout: ritual/reflect/ and ritual/frame/ — organize by beat, not a peer top-level companion/ + reflect/.
  • Companions: inside features/pause; /companion/* routes are pause presentation.
  • UI placement: JSX in screens/<route>/components/; hooks in features/<ctx>/presentation/.
  • Collections: user Archive Collections tab is not on the shipped pause-first surface — quarantined to legacy (spec §7); keep companion_catalog and slot favorites.
  • Branch discipline: one long-lived migration branch; one vertical slice per commit; behavior parity explicit.
  • Other contexts: same module skeleton as pause (§9) — separate *-client-architecture.md scaffolds, not a separate initiative folder.

PostHog product telemetry vs PauseRepository

Design decision
Route pause RPC mutations and analytics_events persistence through PauseRepository ports. Keep PostHog product telemetry in application use-case modules (and adapters like pause-product-analytics) — not behind PauseAnalyticsRepository.
Deviation
None — matches spec intent (server truth vs client analytics projection).
Tradeoffs
Single analytics port — uniform but blurs product vs server events. Split boundaries — two concepts, clearer ownership. Picked split.
Resolution
Documented in README.md pause backlog (May 2026). Incremental shim slices replace direct @/lib/posthog imports in application layer without moving event semantics to infrastructure ports.

Initiative scope vs pause-first scheduling

Design decision

Deviation
None.
