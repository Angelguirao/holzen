Agreed baseline (2026-05)

Captured when pause-client-architecture.md was accepted — not deviations; the interpretation we implement toward.

  • Ritual layout: ritual/reflect/ and ritual/frame/ — not peer top-level companion/ + reflect/ (organize by beat, not “AI”).
  • Companions: inside features/pause; /companion/* routes are pause presentation.
  • UI: JSX in screens/pause/components/; hooks in features/pause/presentation/.
  • Collections: user Archive Collections tab not MVP — strip to legacy (spec §7); keep companion_catalog and slot favorites.
  • Branch: one long-lived migration branch; one commit per vertical slice.
  • Scope vs priority: north star = all bounded contexts on the §9 skeleton; scheduling = pause-first at each slice tier, then subscription/auth/market/… (see README.md phases).
  • Other contexts: same module skeleton as pause (spec §9) — not a separate initiative.

2026-05-20 Initiative scope resolved

Pause-first scheduling ≠ pause-only initiative

Design decision
North star: align all active src/ and extend the pause module template (spec §9) to subscription, auth, market, user, notifications. Scheduling: at each slice tier, finish pause violations before the same tier in another context — pause is reference impl, not the sole domain.
Deviation
None — clarifies wording that was easy to read as “only touch pause until the branch merges.”
Tradeoffs
Pause-only until done — fastest ritual convergence, delays cross-context debt. Strict tier rotation (pause tier 1, then auth tier 1, …) — spreads patterns early, fragments pause ritual moves. Picked pause-first per tier with explicit Phase B/C in migration README.
Open questions
Before Phase B slices: add per-context client-architecture docs or rely on AGENTS + feature READMEs? Decision: add scaffold *-client-architecture.md for each shipped context + client-architecture-overview.md for full src/ rings (Phase 0) before Phase B code slices.
