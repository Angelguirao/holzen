How to use this log

Single append-only audit trail for interpretation across initiatives — when owner docs, tickets, or ADRs do not spell out what to build.

  • Append an <article class="note"> when work involves ambiguity, intentional spec deviation, a tradeoff reviewers should see, or an unresolved question.
  • Tag every note with an initiative (see Active initiatives). Put notes under the matching <h3 id="initiative-…"> section.
  • Skip routine implementation, test-only CI pins, merge cleanup, and behavior-unchanged renames.
  • One note per decision, not one note per commit.
  • Record date, slice title, spec / ticket ref, and status (open | resolved | wont-fix).
  • When resolved, add a Resolution under the same note — do not delete the original.
  • Update this page’s Contents note index when adding a note with a new anchor id.
  • Permanent target changes → update the owner spec in the same PR.

Initiative backlogs live in linked READMEs (e.g. architecture-migration); this file holds decisions, not task lists.
