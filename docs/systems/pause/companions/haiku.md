# Haiku companion (end-to-end)

> **Pause V2:** Haiku artifacts are stored in `pause_ai_artifacts` (kind
> `haiku`) alongside `reflection_text`. Legacy `reflections` columns are
> removed.


**Haiku** is the pause **card** that displays a short, market-anchored haiku generated alongside the reflection text. It is the **only** companion that does not go through **`companion-orchestrate`** — it is produced by the **reflection step** itself.

This page is the **companion-level** view. For **manual vs automatic pause**, **interventions**, **cost limits**, and the full **orchestrator** contract, see the system doc: **[AI-powered pause system](../ai-powered-pause-system.md)** (especially **§7.6** Haiku reference table).

---

## 1. Where Haiku sits in the pipeline

1. **`generateUnifiedReflection`** (`_shared/reflection-generate.ts`) produces a JSON object with **`message`** + **`haiku`** in a single model call. The haiku is part of the same prompt and response as the reflection text.
2. The caller — **`holzen-reflect`** (manual) or **`check-volatility`** (automatic) — extracts the haiku from the response.
3. The caller writes the haiku to **`pause_ai_artifacts`** (kind `haiku`) alongside
   the reflection text (kind `reflection_text`).
4. `HaikuDisplay` in `CompanionSection` renders the haiku card.

Haiku is **never** generated by `companion-orchestrate`, never served from cache or library. It is always a side output of the reflection AI call.

---

## 2. How it differs from other companions

| Aspect | Haiku | Other companions (Signal, Ground, History, Zoom Out) |
|--------|-------|------------------------------------------------------|
| **Producer** | `generateUnifiedReflection` | `companion-orchestrate` → per-type generator |
| **Storage** | `pause_ai_artifacts` kind `haiku` | `pause_ai_artifacts` (per companion kind) |
| **Phase order** | N/A — no library/cache/live/curated chain | Library → cache → live → curated |
| **Lazy loading** | No — arrives with the reflection | Yes — fetched when user taps the card |
| **Cache / dedup** | Dedup via `recentHaikus` passed to the reflection prompt | Per-generator dedup via cache fingerprints + recency hints |
| **Cost** | Included in the reflection model call (no extra API cost) | Separate model calls per generator |

---

## 3. Generation details

- **Model:** Same as reflection — Gemini (`google/gemini-3-flash-preview`, fallback `google/gemini-2.5-flash`) via Lovable AI gateway.
- **Prompt:** The reflection system prompt instructs the model to produce both `message` and `haiku` as JSON keys. Haiku guidelines are part of the reflection prompt (not a separate call).
- **Dedup:** The caller passes up to **5 recent haiku texts** (`recentHaikus`) so the model avoids similar shapes and openings.
- **Quality:** The haiku passes through the same quality gate as the reflection message. No separate `qualityGate` call for haiku specifically.
- **Toggle:** Profile pref **`companion_haiku`** (UI: `prefs.haiku`). When disabled, the reflection model may still produce a haiku in the JSON response, but the UI does not display it.

---

## 4. Feedback

- **Feedback key:** `haiku` → cache type `haiku` (`companion-types.ts`).
- **Mechanism:** `CompanionFeedback` component; feedback is stored via the standard companion feedback path even though haiku storage differs from other companions.
